0. 项目概要

PatchPilot 是一个零第三方依赖、纯 Python 标准库可运行的开源智能体框架，把「补丁生成—安全判定—落地执行」拆成三个相互制衡的角色：提议者（模型，只提「改哪里」）、判定者（确定性规则引擎，只判「能不能改」）、门禁（幂等账本，只管「改过没有、重放没有」）。它不依赖任何大模型 API 即可完成确定性护栏，模型犯错也越不过 12 条硬规则。已通过 91/91 离线断言测试，CI 在 Python 3.10/3.11/3.12 三版本矩阵全部通过，并以 MIT 许可证开源、配套中英双语文档。

1. 项目背景

智能体落地到企业真实工作流时，最大的风险不是「答不对」，而是「改错东西还改两遍」：① 模型可能生成越权、注入或伪造系统标签的补丁；② 同一补丁在重试、网络抖动、并发触发下被重复应用，造成状态污染；③ 出错后无法向审计方证明「为什么这么改」。现有开源 RPA/智能体工具多把判定权整个交给概率模型，缺少一层不依赖模型置信度的确定性护栏。

PatchPilot 的出发点正是这层护栏：让模型保留灵活提议的能力，但把所有「是否放行」的决策收口到可审计、可回放的确定性规则与账本上——这也是它能在多个黑客松赛道被直接复用的原因（见第 3 节）。

2. 技术架构

2.1 三分角色范式

  • 提议者（Proposer）：读取上下文，产出候选补丁与意图说明，不接触执行。
  • 判定者（Verifier）：运行 12 条确定性规则（10 条正则 + 2 条结构化检查），逐条裁决候选补丁，任一命中即拒；规则不看模型置信度，只看代码与元数据。
  • 门禁（Gate）：幂等账本在「执行前」查重，相同账单/补丁重放时直接抑制，绝不二次落地。

2.2 12 条确定性安全规则

10 条基于正则的静态规则（定义在 patchpilot/lint.py，共 10 处 re.compile）覆盖注入、越权、伪造系统标签、工具劫持、凭据泄漏、收款方掉包等模式；2 条结构化检查（超长行 LONG_LINE、吞掉异常 SWALLOWED_EXCEPT）由自检框架强制纳入，合计 12 条。

2.3 零依赖可审计设计

整套核心逻辑仅用 Python 标准库实现，python eval.py 即可在任意干净环境复现 91/91 断言，无安装摩擦、无供应链风险，便于评审方独立复核。

3. 应用场景

  • 真实 RPA 痛点：作者有一年影刀/Uibot 实战经验，企业工作流的补丁治理（权限、幂等、审计）是高频刚需，PatchPilot 的设计直接对应这些痛点。
  • 跨赛复用：同一框架已被映射到 MatrixNEXT「流程自动驾驶」、Nebius×NVIDIA 智能体、苏客松开放命题等多条黑客松赛道，证明其通用性而非一次性拼装。
  • 演示可验证：已录制核心功能演示视频（约 20 秒，⟦提交前在此填入视频链接⟧），展示从提议到门禁抑制的完整闭环。

4. 创新点

  1. 决策权分离：把「提议」与「判定」拆给不同机制，模型只负责灵活提议，确定性规则独占放行权，从根本上杜绝概率模型越权。
  2. 确定性护栏优先于概率模型：不依赖模型自我声明安全性，所有安全判定由可单测的规则引擎完成，结果可证明、可回放。
  3. 执行前幂等账本：在落地「之前」查重，重放攻击与重试抖动不会造成二次修改，是企业级可靠性的关键。
  4. 零依赖可审计：纯标准库、双语文档、CI 三版本矩阵全绿，评审方可一键独立复现全部断言。
